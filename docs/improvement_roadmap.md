# 灵梦work · 迭代综合提升路线图 (100 轮)

> 目标：把 `lingmengwork` 从一个「能跑通多工具链路」的本地 AI 编码智能体面板，持续打磨成工业级的 agent OS。
> 每轮 = 一个可交付、可测试、可回滚的改进单元。本文件是常青 backlog，已完成项打 `[x]`，待办留空。

## 本轮已完成 (批次 1: 工具系统硬化)
- [x] **MCP 工具权限分层**：`mcp.py` 新增 `_classify_mcp_tool`，按危险度把 `web_search/fs_read/code_search/db_query/git_status/...` 归为 `readonly`、`fs_write/git_add` 归 `write`、`shell_exec` 归 `exec`，分别注入 `registry._READONLY_TOOLS/_WRITE_TOOLS/_EXEC_TOOLS`，使 `plan`/`acceptEdits` 模式不再误拦只读工具。
- [x] **工具返回值截断**：`loop.py` 新增 `_truncate_tool_result(res, limit)`，按 `config.agent.tool_result_max_chars`(默认 6000) 截断 `web_fetch/code_search/shell` 等超长输出，防上下文爆炸；并附带 `duration_ms` 用于可视化。
- [x] **repo_map 多语言**：`advanced.py` `_SYM_RES` 从 py/js 扩展到 go/rust/java/c/c++/c#/php/ruby/kotlin/scala/swift/ts/tsx/jsx 等 20+ 语言。
- [x] **tool_kind 全分类**：`loop.py` `tool_kind` 覆盖全部 MCP 工具（fs_*/git_*/shell_exec/code_search/web_*/db_*/demo_*/code_review），链路染色准确。
- [x] **prompt 笔误修正**：12e 由「fs_write 写入代码」改为「write_file（主写工具，写入项目根内）」；明确 web_search/db_query 等外部工具可按名直接调用。

## 施行纪律
- 每轮：写/改代码 → 加/改测试 → `pytest` 全绿 → 重打包 → 重启面板 → 真实 e2e 探针验证 → 记 memory。
- 不破坏既有协议（工具解析、SSE 事件、config schema）。
- 密钥/构建产物永不入 git（`.gitignore` 已覆盖）。
