- 已完成：Phase 55-64 功能闭环（导出→批注→对比→回放→自优化→基线→告警→预算）· Phase 65-67 导航统一

## 三、分阶段计划（每阶段 = 内核/API/前端/测试四件套）

### P1 · observability 页签化（本轮）
- 6 个 section 归 3 页签：🩺 健康度（健康度+工具追踪+瀑布图）｜🤖 编排（编排用量卡）｜📡 事件流（最近 50）
- 沿用工作台页签方案：纯显隐 + localStorage 记忆（key 区分页面）
- **验收**：全量 pytest 全绿；页内 sec-title 全保留

### P2 · 批注编辑（本轮）
- 内核：`update_annotation(anno_id, text?, rating?, tags?)` —— 只更新给出的键，`updated_at` 留痕；沉淀过的批注编辑后重沉淀（幂等，去重由 memory_graph 保证）
- API：`POST /api/superagent/annotations/update {id, text?, rating?, tags?}`（无记录 404）
- 前端：批注行加 ✏️ 编辑 → 行内表单（文本+评分+标签）→ 保存/取消
- **验收**：新增测试 ≥6 例（内核更新/部分更新/404/空 text 拒绝/API e2e/页面 token）

### P3 · cost.html 预算入口在设置中心补镜像（下轮）
- 设置中心「编排与通知」组已有 `agent.daily_budget`，在预算卡加「去设置」链接打通
- **验收**：token 测试 + 手工路径检查

### P4 · 二级页头样式统一（✅ 2026-08-29 调查后关闭）
- 结论：cost/observability/planboard/settings 四页 header CSS 已是同一设计语言
  (同款玻璃底+渐变下划线, 仅对齐细节差异), 抽公共 CSS 收益趋零, 关闭。
- 以 cost.html 的 header 为基准抽 `page-head.css`，逐页替换（纯视觉，无 JS 改动）

### P5 · 收尾
- 全量回归 + 双端推送 + 终极蓝图/记忆落盘
- 打包（PyInstaller 重打包）**继续搁置，等用户点头**

## 四、风险与对策
- **契约破坏** → 每阶段先 grep tests 里的 token 清单，重构后逐文件跑
- **大文件手抄错** → 用锚点提取脚本重组（同工作台页签化方法）
- **静态文件异步落盘** → 每次写完立即回读校验（wc + 关键 grep）
- **GitHub 443 间歇不通** → 直推失败即切 Database API，事后 force-with-lease 对齐（完整 40 位 SHA）
